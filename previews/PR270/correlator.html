Correlator

The correlator correlates the incoming signal with the local code replica at several code-phase offsets (early, prompt, late, …). Each TrackedSignal holds its own correlator, so a multi-signal satellite carries one per signal.

Why early/late spacing matters

The PLL discriminator and C/N₀ estimator consume the prompt; the early and late accumulators give the DLL the slope of the code-correlation triangle. Early minus late crosses zero when the replica is aligned, and its sign tells the DLL which way to push.

Notation: d is the early-to-late spacing in chips (d = 0.5: E and L ½ chip apart), ε the code-phase error in chips, B_fe the front-end (analog + ADC) bandwidth, T_chip = 1 / f_code the chip period, f_code the chip rate (1.023 MHz for GPS L1 C/A) and Fs the sampling frequency.

  • Thermal-noise jitter decreases as d shrinks, because the noise on E and L is correlated and partially cancels in their difference (Van Dierendonck, Fenton & Ford, "Theory and Performance of Narrow Correlator Spacing in a GPS Receiver", NAVIGATION 39(3), 1992). A wider spacing only smooths a time-multiplexed (dither) DLL; Tracking.jl computes E, P and L simultaneously from the same samples.
  • Multipath error also decreases as d shrinks, as the discriminator samples the correlation function nearer the peak (same paper).
  • Robustness to dynamics decreases as d shrinks. The discriminator is linear only over |ε| < d/2 (the pull-in range T_DLL, Springer Handbook of GNSS, §14.4.4); beyond it the slope drops to zero with the sign still correct. The lock rule of thumb 3σ_DLL + ε_D ≤ T_DLL ≈ d/2 (eq. 14.57) leaves a narrow d less budget for dynamic stress error ε_D, which is why NovAtel's narrow-correlator design widens d during acquisition and narrows it once locked.
  • Front-end bandwidth caps the gains: below roughly d ≈ 1 / (B_fe · T_chip) the band-limited peak is rounded, the slope flattens and jitter grows again. Van Dierendonck reports d ≈ 0.1 as optimal at 8 MHz on L1 C/A.

The sample rate sets the minimum d

preferred_early_late_to_prompt_code_shift is the early-to-prompt (and prompt-to-late) shift, so d is twice it. It is rounded to the nearest whole sample shift, at least one, so the realized spacing is d = 2 · max(1, round(shift · Fs / f_code)) · f_code / Fs chips. A d ≈ 0.1 on L1 C/A needs Fs ≥ 20 · f_code ≈ 20.46 MHz; at 4 MHz d saturates at 2 · 1.023e6 / 4e6 ≈ 0.51 chips whatever the preferred value.

The VeryEarlyPromptLateCorrelator adds a very-early / very-late pair for the multi-peaked correlation function of BOC signals like Galileo E1B: the inner pair locks the central peak, the outer pair disambiguates it from the side peaks.

Default Correlators

get_default_correlator returns, per signal type:

  • VeryEarlyPromptLateCorrelator for the BOC-family signals GPS L1C-D, GPS L1C-P, Galileo E1B, Galileo E1C and BeiDou B1C;
  • EarlyPromptLateCorrelator for every other signal.

Correlator outputs

Each completed integration within a processing chunk is recorded as a CorrelatorOutput, collected per signal and consumed by the Doppler estimator after the chunk (see Chunked Doppler updates). An external correlator producer (e.g. an FPGA) can build these itself and feed them straight to the estimator — see External correlator producers.

get_correlator_outputs(t)

The CorrelatorOutputs this signal completed in the current chunk, in order. The Doppler estimator consumes and clears them, so read them inside a custom estimator or right after a bare downconvert_and_correlate!. See Chunked Doppler updates.

Post-correlation filter

A post-correlation filter reduces the per-antenna taps to the single channel the Doppler and C/N₀ estimators see. It declares its combining weights through get_weights and Tracking applies them, so the measured noise covariance is reduced through the same weights and the C/N₀'s numerator and denominator describe one channel (see CN0 Estimator).

DefaultPostCorrFilter is the identity for a single antenna and selects the last element for an array. For an array a beamformer is the natural override; see Tracking State.

Adjusting the spacing of the stock correlator

Changing d needs no custom correlator: pass d / 2 in chips as preferred_early_late_to_prompt_code_shift (here d = 0.2):

julia> using Tracking, TrackingLoops, GNSSSignals

julia> using Tracking: Hz

julia> track_state = TrackState(; signal = GPSL1CA());

julia> sat = TrackedSat(GPSL1CA(), 1, 50.0, 1000.0Hz;
                        correlator = EarlyPromptLateCorrelator(
                            preferred_early_late_to_prompt_code_shift = 0.1,
                        ));

julia> track_state = add_satellite!(track_state, :default, sat);

julia> get_correlator(track_state, :default, 1, 1).preferred_early_late_to_prompt_code_shift
0.1

VeryEarlyPromptLateCorrelator exposes the inner (preferred_early_late_to_prompt_code_shift, default 0.15) and the outer (preferred_very_early_late_to_prompt_code_shift, default 0.6) shift. Either is subject to the sample-rate floor above.

Changing the spacing of a satellite that's already tracking

The sat, signal and correlator are immutable, so build a replacement sat with Accessors.@set and write it into the slot with Dictionaries.set!:

julia> using Accessors, Dictionaries

julia> sat     = track_state.groups[:default].satellites[1];

julia> new_sat = @set sat.signals[1].correlator.preferred_early_late_to_prompt_code_shift = 0.7;

julia> Dictionaries.set!(track_state.groups[:default].satellites, 1, new_sat);

julia> get_correlator(track_state, :default, 1, 1).preferred_early_late_to_prompt_code_shift
0.7

@set keeps everything else, including the in-flight accumulator, and the TrackState's concrete type does not change.

Custom Correlators

Write a correlator for a layout the stock types lack: extra taps, asymmetric shifts, or a different prompt index. Subtype AbstractCorrelator (or AbstractEarlyPromptLateCorrelator to inherit the early/late accessors) and implement:

MethodPurpose
get_accumulators(c)Return the backing storage of accumulators (e.g. an SVector of ComplexF64).
get_num_accumulators(c)Return how many accumulators the correlator holds. Defaults to size(get_accumulators(c), 1) — only override if your layout differs.
update_accumulator(c, accumulators)Construct a fresh correlator instance with the given accumulators (immutable update).
get_correlator_sample_shifts(c, sampling_frequency, code_frequency)Return an SVector{N,Int} of sample offsets relative to the prompt, ordered from latest replica to earliest.

get_prompt_index defaults to the middle accumulator; override it for an asymmetric layout.

Skeleton

A 7-tap correlator, e.g. for a multipath-mitigation discriminator that fits a slope over several early/late taps:

julia> using Tracking, TrackingLoops, GNSSSignals, StaticArrays

julia> using TrackingLoops:
           AbstractEarlyPromptLateCorrelator,
           get_initial_accumulator,
           calc_preferred_code_shift_to_sample_shift,
           NumAnts,
           NumAccumulators

julia> struct MultiTapCorrelator{M,T} <: AbstractEarlyPromptLateCorrelator{M}
           accumulators::SVector{7,T}
           tap_spacing_chips::Float64
           # Pin M from the accumulator element type, as TrackingLoops' EPL does.
           function MultiTapCorrelator(
               accumulators::AbstractVector{SVector{M,T}}, tap_spacing_chips,
           ) where {M,T<:Complex}
               new{M,SVector{M,T}}(accumulators, tap_spacing_chips)
           end
           function MultiTapCorrelator(
               accumulators::AbstractVector{T}, tap_spacing_chips,
           ) where {T<:Complex}
               new{1,T}(accumulators, tap_spacing_chips)
           end
       end

julia> # Keyword constructor, like the EPL one
       function MultiTapCorrelator(; num_ants::NumAnts = NumAnts(1),
                                     tap_spacing_chips = 0.1)
           MultiTapCorrelator(
               get_initial_accumulator(num_ants, NumAccumulators(7)),
               tap_spacing_chips,
           )
       end;

julia> TrackingLoops.update_accumulator(c::MultiTapCorrelator, accumulators) =
           MultiTapCorrelator(accumulators, c.tap_spacing_chips);

julia> function TrackingLoops.get_correlator_sample_shifts(
           c::MultiTapCorrelator, sampling_frequency, code_frequency,
       )
           s = calc_preferred_code_shift_to_sample_shift(
               c.tap_spacing_chips, sampling_frequency, code_frequency,
           )
           SVector(-3s, -2s, -s, 0, s, 2s, 3s)
       end;

Build the TrackState from a sat carrying it, so the slot type is the custom correlator's:

julia> using Tracking: Hz

julia> sat = TrackedSat(GPSL1CA(), 1, 50.0, 1000.0Hz;
                        correlator = MultiTapCorrelator(tap_spacing_chips = 0.1));

julia> track_state = TrackState(GPSL1CA(), sat);

julia> get_num_accumulators(get_correlator(track_state, 1))
7

The default DLL discriminator reads only the outermost early/late pair, so pair a multi-tap correlator with a Custom Doppler Estimator. TrackingLoops' src/correlators/early_prompt_late.jl and very_early_prompt_late.jl show the full pattern, including multi-antenna accumulators.
